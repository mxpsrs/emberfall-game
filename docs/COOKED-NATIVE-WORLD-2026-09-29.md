# Direct native Scene loading — 29 September 2026

The build now cooks the canonical world once, including the committed editor layer, into versioned `world-native.json`. Runtime and editor load this document once and connect existing gameplay projections without rerunning the twelve category conversions or serializing/reloading the world between them. The construction graph remains necessary for legacy lexical references; its identity is verified against the cooked artifact. Character-specific quest, inventory and session state is restored after connecting canonical definitions.

A complete newer editor Scene wins outright, including deleted entities. A changed partial editor layer, missing/incompatible cooked asset, or old-layout save retains the existing migration route. Partial live editor changes can therefore still incur the older loading cost until incorporated into the build or saved as a complete canonical Scene. Terrain edits are applied separately. No account data is baked into the asset.

The native integration test loads all 259 scenes and 20,665 entities with exactly one native load, zero serialization and no mapper conversion. It checks tutorial entry, cyclic building/door bindings, door state, transient actor writes, saved inventory/bank/XP, editor transforms/save/reload, partial-layer fallback and authoritative deletions after a second boot.

The production-world real Filament NOOP probe completed 32 frames. Compared with the previous local run, world setup dropped from 26.35 s to 8.98 s, while construction decoding increased from 0.95 s to 4.04 s and first draw remained 14.95 s. The startup subtotal was 27.97 s versus 42.41 s. The candidate ran concurrently with integration tests, so these are indicative local CPU measurements, not a controlled device benchmark. Subsequent draw median was 142 ms versus 121 ms; this work does not establish a steady-frame improvement. Network time and GPU execution are excluded. Physical iPhone performance and hosted 39-player capacity remain unverified.

Static asset compression now includes eligible text/binary resources above 1 KiB (previously 64 KiB), preserving exact decoded response bytes and identity fallback. No server protocol, schema or account reset changes are included. Generated cooked data is build output, not tracked source. Run `npm run build`, `node tests/prebuilt-native-world.cjs`, and `node tests/built-assets.mjs` for release verification. See the companion QA JSON for timings and checks.
